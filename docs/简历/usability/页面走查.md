# Git Agent（简洁版）页面走查：每个页面是干嘛的、用起来什么感觉

> 走查日期：2026-09-07。方式：真实启动应用，以"第一次用的新手"视角逐页点看。
> 截图存在 `docs/简历/usability/` 目录（00~07）。走查只做了浏览，没有改动任何仓库数据。

## 先记住一张地图

整个产品只有 **8 个屏幕**：启动页（项目列表）+ 左侧导航的 7 个页面。
7 个页面分两组：**"每天都会用"**（保存改动、远程同步、历史、工作线、临时收起）和**"偶尔使用"**（高级工具、设置）。
每个页面右边都有一个固定的**"操作解释器"**——永远告诉你三件事：**影响哪里、能否撤回、风险等级**。这是这个产品最特别的设计。

---

## 0. 项目列表（启动页）  📷 00-projects.png

**一句话**：你的"项目大门"——打开、新建、下载项目都从这里开始。

**实际功能**：三张卡 = 打开电脑里已有的项目 / 新建一个本地项目 / 粘贴网址从 GitHub 下载。下面列出已打开的项目，可以改名字、关闭。

**使用体感**：✅ 很友好。三张大卡片，每张下面有一行小字解释。新手第一屏不会被吓到。
**小难点**：顶部"＋新增工作目录"按钮和页面标题"新增工作目录"重复出现，稍微有点绕。

---

## 1. 保存我的改动（核心流程 1/3）  📷 01-launch.png

**一句话**：把今天的修改"存一个档"，存在自己电脑里，不上传。

**实际功能**：列出所有改动的文件 → 勾选要保存的 → 写一句说明 → 保存（= Git 的提交 Commit）。还能撤销上一次保存、看每个文件"什么时候建的、什么时候改的"（时间追溯）。

**使用体感**：✅ 三步编号很清楚；文件后面直接显示"最后修改：几点几分"，很人性化；"原软件称为'暂存(Stage)'"这种对照很贴心。
**小难点**：⚠️ "全部放进这次保存 / 全部暂不保存 / 放弃全部修改…"三个按钮排在一起、文字都很长，新手要停下来分辨半天——尤其"放弃"是危险操作，和前两个长得太像。

---

## 2. 和远程同步（核心流程 2/3）  📷 02-sync.png

**一句话**：和团队共用的网络仓库对齐——先检查、再下载、最后上传。

**实际功能**：Fetch（检查有没有新东西）/ Pull（把别人的更新拿下来）/ Push（把我的提交传上去）。

**使用体感**：✅ 页面顶部就教了安全顺序"先检查，再下载，最后上传"。这次走的项目没连远程，页面没有报错，而是温和地提示"还没连接远程仓库"并给出"打开仓库设置"按钮——**失败也有引导**，这一点很多专业软件都做不到。
**小难点**：⚠️ 没连远程时页面中间一大片空白，稍微有点"是不是坏了"的错觉。

---

## 3. 查看历史版本（核心流程 3/3）  📷 03-history.png

**一句话**：翻看这个项目的"过去每一次存档"，默认只读、随便看、不会改坏。

**实际功能**：提交列表、按日期/拓扑排序、搜索、两个版本对比、回到旧版本、从旧版本开新分支。

**使用体感**：✅ "默认只读，改历史才需要二次确认"——这句话直接消除了新手最大的恐惧。
**小难点**：⚠️ 空状态文案重复（"还没有提交"和两处"没有提交。"同时出现），而且没有告诉我下一步该去哪——其实应该引导"先去第 1 步保存一次改动"。

---

## 4. 切换工作线  📷 04-branches.png

**一句话**：开一条"平行世界"来试新想法，试坏了随时丢掉，不影响主线。（Git 叫分支 Branch）

**实际功能**：看本地分支、新建分支、切换分支；合并、变基、远程跟踪、删除都在这页。

**使用体感**：✅ "分支是一条平行工作线"这个比喻好懂；"给它一个用途明确的名字，例如 feature/simpler-home"——连起名都教了。
**小难点**：⚠️ 这页是全程术语最密的一页：合并、变基、远程跟踪、删除四个概念一起出现。虽然每个都有一行解释，但新手第一次看还是会晕。"变基"这种词即使翻译了也偏专业。

---

## 5. 临时收起改动  📷 05-stash.png

**一句话**：活干到一半必须去干别的？把半成品放进"临时抽屉"，回来再取出来。（Git 叫 Stash）

**实际功能**：收起 / 恢复 / 删除临时改动，强制写一句"为什么收起"。

**使用体感**：✅ 场景感最强的一页——"工作没做完但必须切换工作线时"，一句话就知道什么时候用它；按钮直接写"临时收起 12 个改动"，数量可见。
**小难点**：⚠️ 四个收起范围选项（仅 Staged、保留已暂存、未跟踪、被忽略）对新手中了"术语回潮"——前面好不容易把 Stage 翻译成"放进保存"，这里又冒出来了。

---

## 6. 高级工具  📷 06-tools.png

**一句话**：低频但专业的功能收纳间——合并冲突、整理历史、标签、补丁、大文件（LFS）都在这。

**实际功能**：合并另一条工作线 / 解决合并冲突（三栏工具 + AI 建议）/ 整理提交历史（变基）等。

**使用体感**：✅ 页面顶部直接声明"这些不会挤占新手主路径，危险操作仍会二次确认"——定位清晰；每个工具下面用三行字说清"先选目标→逐个处理→验证后继续"。
**小难点**：基本没有。收纳合理，进来的人本来就是找专业功能的。

---

## 7. 设置与电脑工具  📷 07-settings.png

**一句话**：所有"配置"都在这里：外观、语言、SSH、身份、AI 助手、仓库规则。

**实际功能**：主题字号语言 / SSH 密钥 / 提交署名 / API Key / `.gitignore` 编辑 / 打开访达和终端。

**使用体感**：✅ 每个按钮上方都先写"这是干什么的"再给按钮；**AI 隐私承诺直接写在界面上**："只在你主动使用 AI 合并建议时请求模型；普通 Git 操作不需要 API Key。"——这句话是整个产品 AI 叙事的落地。
**小难点**：基本没有。信息量大但都分好了卡片。

---

## 总结：这个产品的"体感画像"

**做得好的（已是差异化优势）**：
1. 每页右侧的"影响哪里 / 能否撤回 / 风险等级"三件套——安全感是设计出来的，不是运气。
2. 术语对照表常驻（Commit=保存一个本地版本，Stash=临时收起……）。
3. 失败态有引导（没连远程不报错，给下一步按钮）。
4. AI 隐私承诺写在界面上，不是藏在文档里。

**四个走查问题及修复结果（2026-09-20）**：
1. ✅ **危险操作已隔离**："放弃全部修改"与安全批量按钮分区显示，并使用红色危险提示和结果说明。
2. ✅ **术语已统一**：临时收起页不再出现"仅 Staged"，统一使用"已经选入下一次保存的改动"。
3. ✅ **空状态已有下一步**：历史页无版本时只显示一处说明，并提供"去保存第一个版本"按钮。
4. ✅ **高级分支操作默认折叠**：新建和切换保持在主路径；合并、变基、远程跟踪和删除按需展开。
