**独立开发项目：Git Agent Clear —— AI 时代的新手向 Git 客户端｜独立开发者 & 产品负责人｜2026.03—至今**

**项目描述**

背景与目标：Git 是开发者标配工具，但对新手门槛极高——免费客户端功能阉割（GitHub Desktop 无交互式变基），全功能客户端收取订阅费（Tower $69/年起），且业内几乎没有产品把"防误操作"作为核心设计。我的判断是：AI 编程时代，代码产出越来越容易，"看懂改动、安全提交、可反悔"反而成为瓶颈，新手需要的不是功能更多的工具，而是"每个操作都告诉你会发生什么"的工具。目标是在保留专业版完整能力的前提下，做出一套引导式界面，并规划 AI 合并建议能力。

核心职责：

1. 产品定义与竞品分析：以"原版专业界面"为对照组，完成横纵向竞品分析（横向 8 款 Git 客户端、纵向 5 层替代方案），确立"免费全功能 + 引导式安全操作"的差异化空位，输出立项报告与 PRD；
2. 引导式体验设计：将 Git 全工作流重组为"保存改动 → 远程同步 → 查看历史"三步主路径 + 7 个页面，设计常驻"操作解释器"（每个操作标注影响范围、能否撤回、风险等级）与 Git 术语对照表，危险操作全部二次确认；
3. AI 合并建议规划：设计"确定性规则优先于模型、AI 只建议不执行、敏感文件不出仓"的三条边界，规划五阶段路线图并落地阶段一（4 条确定性合并规则 + 5 类安全过滤）；
4. 质量验收与可用性迭代：建立"实操 / 回归 / 界面"三层验收口径，完成 8 页面可用性走查并沉淀 4 个 V2 优化点进入需求池；使用 AI 编程工具完成全部实现。

**项目结果**

- 独立交付可安装的 macOS 桌面应用（代码签名 + DMG 校验通过），9 大功能域与专业对照版 100% 功能对齐，逐条验收无占位功能；
- 建立 667 项自动化测试（0 失败）与 13 个里程碑版本管理，保证独立开发下的交付质量；
- 完成 PRD、立项报告、竞品分析、可用性走查 4 份产品文档；AI 合并建议已落地确定性规则层，模型接入无需改造现有交互。
